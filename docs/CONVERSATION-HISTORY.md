# 会话档案与恢复

会话档案可以搜索本人全部历史标题，按普通对话、应用和行动搭档分类，也可以按自建分组和未分组查看。每次打开一页，继续加载更早的记录；搜索和清理覆盖当前筛选的全部页数。

置顶、重命名和移动分组沿用当前记录的版本。其他窗口已经修改记录时，本次操作会被拒绝，刷新后再决定。删除分组只把其中的对话移回未分组，保留原消息。

清理会话前显示范围、数量和仍在生成的对话数。清空未置顶会保留置顶记录；确认后数据发生变化时，整次旧确认失效。每次最多手选 500 段，清空未置顶不受已加载页数限制。

移入回收站后停止该对话尚未完成的生成，已产生的费用继续依原回执说明。恢复带回原消息、版本分支和附件引用，保留原费用记录；恢复本身不会生成回复或再次扣费。附件能否使用仍取决于个人文件的实际状态和保存期限。

移除正在阅读的对话时，未发送的文字和附件继续留在编辑区。操作回执丢失时保留原内容，刷新只核对记录，不自动再次清理。切换账号或筛选条件后，旧确认不能提交到新的范围。

界面支持简体、繁体和英文，原始标题、分组名称和草稿不被改写。支持键盘选择、独立列表滚动和减少动态效果的偏好。

## 接口与兼容

- `GET /api/conversations/history`：`kind`、`scope`、`q`、`folder`、`limit` 与不透明的 `cursor`；默认每页 40 段，最多 50 段。
- `POST /api/conversations/status`：读取本人指定记录的最新状态，每批最多 200 段。
- `POST /api/conversations/bulk-preview`：核对完整范围，返回本次确认标识。
- `POST /api/conversations/bulk-delete`：新页面提交 `preview` 和确认标识；旧参数保留兼容。
- `POST /api/conversations/:id/trash` 与 `POST /api/conversations/:id/restore`：携带 `expectedVersion`。

升级执行 `0042_conversation_versions.sql`，新增会话与分组的版本字段及历史索引，原记录默认版本为 1。旧列表接口保留最近 100 条的行为，新页面使用完整分页接口。数据库、站点配置、供应商凭据和个人文件不随代码发布。
