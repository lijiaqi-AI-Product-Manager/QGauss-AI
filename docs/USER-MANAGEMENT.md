# 用户管理

用户中心把账号身份、会员与次数、余额、登录记录及会话入口放在同一处。页面支持简体中文、繁体中文、英语和三种外观，手机使用单列卡片；动效遵循系统及产品的减弱动态设置。

- `GET /users`：管理员组合检索。关键词、独立用户名及邮箱、账号状态、角色、分销资格与注册日期取交集；`%`、`_` 按原文查找。统计来自完整查询结果。页码上限 1000000，每页最多 100 条，默认 20 条。列表与统计在同一读取事务中，按创建时间和编号倒序；`asOf` 固定创建时间上界，不冻结后续状态变化。
- `GET /users/:id`：管理员读取用户资料、只读权益概览及活动数量。不创建余额账户，不执行每日额度重置。会员今日额度按当前上海日期展示，处理中预留单列展示。
- `GET /users/:id/activity`：按 `kind=grants|logins|conversations|management` 分页读取，默认每页 20 条、最多 50 条。页面使用每页 10 条，沿资料读取时间限定创建时间上界，新登录不会挤动后续页；重新读取资料会更新该上界。登录记录不包含原登录账号与失败内部原因；权益记录不返回套餐内部快照；会话不返回系统指令或参数。会话链接带上用户与会话条件进入记录中心。
- `PATCH /users/:id/status`：保留禁止禁用当前管理员的约束。新页面提交 `expectedUpdatedAt`；资料已变化返回 409。同一状态重试不再次吊销凭证，禁用与凭证吊销同事务完成。写入前重新确认当前管理员仍然有效。

手工发放继续调用 `POST /balance/upgradeBalance`，受商业化开关和管理员权限控制。填写后先核对收取用户及所有增量。新页面携带 `requestKey` 与资料版本，发送前把原内容保存到当前管理员的浏览器会话存储；网络中断或回复不完整时保持待确认状态，恢复时只提交原请求。存储不可用时不发送。

服务按管理员与请求编号产生唯一凭据号，在同一事务中完成查重、余额变动及凭据保存。同一请求重试返回原凭据；更改收取用户、次数、金额、天数或备注返回 409。已成功请求可在用户后续资料变化或禁用后核对凭据，失效管理员不能继续核对或发放。新请求要求收取账号有效且资料版本一致。单项次数最多 1000000、会员天数 -1 至 36500，-1 为永久；不接受空发放，检查账户整数容量。原调用方不提供请求编号时保留原契约，不能获得请求级去重保证。会员已永久有效时，正天数增量保留永久期限。

首次请求明确被拒绝时可以结束核对或重新调整。已有结果不明的请求，不能因后续权限或商业化开关拒绝而改成新发放；保留原内容，待权限与开关恢复后继续核对。

验证覆盖：组合检索及字面匹配、稳定分页、公开字段边界、只读详情、状态重试与事务回退、并发发放、同请求冲突、权限变化、发放中断恢复、重复点击、跨用户迟到回复、三种语言和真实组件内的点击链路。独立临时数据验证不修改正式账户或余额。

## 资料维护与登录设备

管理员可按备注原文筛选，查看仅管理员可见的备注，并在核对修改前后内容后保存。本人资料与登录返回值不包含管理备注。分销资格开通时按站点默认比例准备推广账户；已有比例、独立启停、邀请与账目保留。撤销资格也保留历史。已开通但缺少推广账户的历史记录可明确修复。

- `PATCH /users/:id/management`：携带 `expectedUpdatedAt`、`requestKey` 及明确修改的 `adminNote` 或 `isDistribution`；资料变化返回 409。备注最多 2000 字，空文本表示清空。
- `GET /users/:id/sessions`：管理员读取账号尚未撤销和到期的登录，按同次登录的轮换链合并；不以最近登录日志推断设备在线。本人使用 `GET /users/sessions`。每页最多 50 条，界面每页 8 条。`asOf` 限定首次登录创建时间，不冻结之后的结束、到期或使用状态。
- `POST /users/:id/session-actions`：管理员核对单次或全部登录后结束。本人使用 `POST /users/session-actions` 结束某次其他登录或全部其他登录，当前登录保留。单次操作不会影响其他登录；全部下线不改变账号启停状态。
- `POST /users/:id/account-actions/resolve`：核对保留的原操作。已生效时返回原凭据；尚未生效时记录明确的未生效结果，之后迟到的原提交也不能重新生效。本人入口是 `POST /users/account-actions/resolve`，仅支持自己的登录操作。

资料与登录操作在同一写入事务内重新检查操作者身份、权限及当前登录，按请求编号返回唯一结果。请求编号复用时更改内容、目标或范围会拒绝。新的下线请求同时核对资料版本与完整登录范围，登录新增、到期或轮换后须重新核对；受保护账号与当前管理登录不可从这些入口强制结束。

页面在发送前保存核对的原内容。重复点击不会创建第二次操作，结果未知时可继续核对或明确收尾；切换账号不会把原结果显示到另一人名下。维护历史保留收取账号、操作者、变化内容与凭据号，不显示令牌与内部校验值。
