# 扫码登录与身份关联

登录页支持邮箱／登录名、手机和扫码三种入口。扫码需要已配置的公众号服务；尚未开放时明确提示，并保留其他登录方式。在微信内打开时，也可选择当前手机授权。页面只在二维码实际准备完成后展示图片，等待、确认、到期与结果待核对分别展示。

## 账户与首次安全设置

已有扫码身份进入原账户；首次身份在注册开放、协议同意及邀请码要求满足后创建独立账户。账户可以暂不填写邮箱，不生成虚构邮箱地址，也不以随机密码向用户提供密码登录。新用户进入个人空间后，可验证本人手机号、两次填写第一把密码；成功后结束之前的登录，再通过手机与密码进入。已有作品、余额与身份关联保留。

已有密码的账户可在个人空间确认当前密码，再扫描本人身份完成关联。一个身份只能连接一个账户，一个账户在同一服务配置下只能连接一个身份。关联不会合并两个账户，不转移作品、权益、手机号或密码。首次设置、绑定、注册与找回密码的验证码分别使用，不能互相替代。

## 开启服务

在服务端设置以下配置，回调地址固定为公开站点的 `/api/auth/external/notify`，网页授权返回固定为 `/api/auth/external/callback`。凭据只保存在服务端，不返回浏览器。

| 配置 | 用途 |
|---|---|
| `EXTERNAL_ENABLED=true` | 开启服务 |
| `EXTERNAL_APP_ID`、`EXTERNAL_APP_SECRET` | 公众号应用与服务端凭据 |
| `EXTERNAL_CALLBACK_TOKEN` | 回调校验口令 |
| `EXTERNAL_ENCODING_AES_KEY` | 消息加密密钥 |
| `EXTERNAL_PUBLIC_ORIGIN` | 本站公开 HTTPS 地址，不包含路径、查询或账号信息 |
| `EXTERNAL_ACCOUNT_ID` | 可选的公众号原始标识，用于额外核对消息接收方 |

公众号需要分别具备临时二维码、网页授权及消息回调权限。消息推送仅接受加密方式。服务使用固定提供方地址，不接受任意外部目标。管理员通过 `GET /api/auth/external/configuration` 核对配置准备状态；该结果只检查配置，不证明真实扫码、授权、消息投递或账号权限已验收。`realProviderAcceptanceVerified` 不作为真实验收记录。

站点设置 `security.externalLoginEnabled`、`security.externalRegistrationEnabled` 分别控制入口与首次注册；首次注册同时遵守总注册开关及邀请码要求。`security.externalDailyLimit` 默认为最近二十四小时一千次申请，另有来源与同时等待数限制。短信首次设置另外需要短信服务配置。

## 等待、恢复与结束

连接有效期最多五分钟。页面隐藏时停止定时核对，返回后读取原结果；网络中断、页面恢复或重复点击不会自动申请新的二维码或重新交换授权代码。浏览器无法保存处理编号时，不提交新的申请。浏览器只保留当前页签内的编号与随机校验值，不保存密码、号码、验证码、二维码、授权地址或登录凭据。

扫码消息必须同时符合签名、加密、接收方、时效、原场景和原二维码凭据；重复消息不重复处理。手机授权需要发起浏览器的受保护凭据，同一授权代码只交换一次。登录结果有短期恢复窗口，成功接收后清除保存的结果；未被接收的结果到期或明确结束时，结束对应登录，保留已创建的账户。已完成的身份关联不会因关闭等待卡片而撤销。

## 升级与验证范围

本次迁移增加独立身份、连接申请、消息去重和加密服务状态表。已有用户默认保留密码登录能力；新增外部账户在本人完成首次设置前没有密码登录入口。升级前需要加密备份、完整性核对和数据库副本演练；回退旧页面与服务时仍需保留兼容新字段的数据库访问组件。

本地检查使用合成账户、独立数据库、独立加密向量和模拟提供方，覆盖真实 HTTP 路由、浏览器回调、关联冲突、过期清理及首次密码设置。真实公众号、短信到达、外部网络与实际手机体验仍需配置后分别验收。
