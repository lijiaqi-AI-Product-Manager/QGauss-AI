# 对话附件

一条问题最多选择 9 个附件，同时处理 3 个上传。附件卡片分别展示排队、上传、保存、核对、就绪和失败；失败或结果未确认的文件会暂停发送。手机附件列表独立滚动，问题和发送按钮继续可用。界面支持简体、繁体和英文，文件原名保持原文。

上传与发送是两个独立动作。选择、重试、核对、从个人文件复用、回收与恢复都不会创建回答或消耗模型次数。用户明确发送前，会核对文件归属、保存状态和文档能否读取；核对期间的问题编辑、账户切换和会话变化会取消这次发送准备。重新生成先核对原提问的附件，失败时保留原回答和当前草稿。

网络中断时先读取原上传记录，不自动重新传文件。明确失败后，用户可重新上传同一份原文件；更换内容需重新选择附件。移出编辑区不会删除个人文件。已回收的文件不能发送，恢复后沿用原文件标识；更早轮次的不可用附件以说明保留，不阻挡新的无附件问题。

| 接口 | 用途 |
|---|---|
| `POST /upload/requests/:key` | 以 UUID 和 `expectedVersion` 接收原文件 |
| `GET /upload/requests/:key` | 本人只读核对原上传 |
| `POST /upload/attachments/check` | 核对本人所选文件，不返回文档正文 |

首次上传使用版本 0。重复初始请求沿用原记录；明确失败后的重试使用该记录的当前版本。同一标识不能更换文件字节或文件名，其他账户和管理账户不能读取其上传回执。服务重启后核对已暂存的原始字节；完整文件继续落定，未完成的上传保留明确重试入口。

迁移 `0041_upload_receipts.sql` 新增上传记录表，不改写既有文件和账本。发布前停止生成、上传及维护工作，备份数据库、存储与运行配置。保留与本版本配套的数据库客户端；回退时先保全新增记录，不直接覆盖升级后的数据。

相关检查覆盖并发及迟到请求、写入结果丢失、重启恢复、存储不可用、文件完整性、账户隔离、缓存失效、历史文件、草稿保留、明确重试与窄屏操作。真实存储服务、模型文件能力和更多手机设备仍需单独验收。
