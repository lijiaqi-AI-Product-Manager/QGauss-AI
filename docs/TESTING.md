# 测试与发布检查

安装依赖并准备开发数据库后，执行 `npm run verify`，依次检查发布内容、产品品牌、类型、未使用导出、构建、产物、单元与组件测试，以及隔离 HTTP 测试。

HTTP 测试复制开发数据库，使用临时存储与本地模拟服务；结束后清理副本。测试子进程关闭实际邮件投递。不要把生产运行配置或真实供应商凭据用于测试。

SQLite 服务测试使用运行服务的事务入口，覆盖独立客户端并发、回滚、超时及后续恢复。HTTP 恢复测试保留独立外部连接，核对进程之间的锁与重复处理规则。

应用测试覆盖私有创建、编辑版本、投稿审核、奖励原子提交、分享与撤回、回收站恢复及中断核对。访客仅能读取有效公开资料；编辑器设定只对作者和可审核范围内的管理账户开放。页面测试检查草稿保留、未知结果不自动重发、账户切换和应用对话版本核对。

已有服务占用默认端口时，通过 `E2E_PORT` 和 `FAKE_PORT` 选择空闲端口。Windows 长测试需要等待同一进程完成，不应因等待超时重复启动套件。

部署配置另运行 `npm run verify:compose`。该检查验证 Compose 与文件复制关系，不构建镜像，也不证明容器已经运行。

页面预览使用合成数据，与产品 API 隔离：

```bash
# QGAUSS_PREVIEW_DIR 设置为本机专用输出目录
npm run preview
```

预览素材和接口替身只用于测试，不进入生产入口。页面测试覆盖交互、权限、异常与身份切换；真实设备、外部收信、模型效果、商户结算、负载和离机恢复需要单独验收。

Pull Request 中记录实际执行的检查、结果和未覆盖项。测试数量随功能变化，不使用历史数字替代本次结果。
